# NexaCare Hospital Management SaaS — Hospital Branding & Export Developer Guide
## Engineering Standards, Architecture Patterns & Best Practices for Multi-Tenant Document Generation

---

## 1. Overview & Golden Rules

Every document generated by NexaCare (Excel, CSV, HTML/Playwright PDF, ReportLab Platypus PDF) represents an official hospital artifact. In our multi-tenant SaaS architecture, all documents must adhere to four golden rules:

1. **Always Use `BrandingResolverService`**: Never query hospital branding directly via ad-hoc SQL or ORM lookups. Never hardcode hospital names, logos, or contact information.
2. **Always Sanitize Spreadsheet Cells**: Every string written to an Excel sheet or CSV export MUST pass through `sanitize_excel_row()` / `sanitize_excel_cell()` or `sanitize_csv_row()` / `sanitize_csv_cell()` to prevent **CWE-1236 Formula Injection**.
3. **Respect Rendering Engine Media Requirements**:
   - For **HTML / Playwright (Chromium)**: Use `branding.logo_data_uri` (Base64 data URI). Chromium blocks raw local file paths (`file://` or `C:/...`) under its security sandbox.
   - For **ReportLab Platypus**: Use `branding.logo_path` (verified OS file path) or `create_reportlab_header_flowables()`. ReportLab cannot parse data URIs.
4. **Preserve Native Numeric Types**: When exporting numbers, pass them as native `int` or `float` types. Do not format them as string-prepended currency before passing to sanitizers, or you may break user spreadsheet arithmetic.

## 3. Implementation Recipes

### 3.1 Recipe 1: Implementing an OpenPyXL Excel Tabular Export

Follow this standard pattern whenever adding a new Excel export endpoint:

```python
from io import BytesIO
from openpyxl import Workbook
from app.services.branding_resolver_service import BrandingResolverService
from app.utils.excel_security import sanitize_excel_row
from app.utils.excel_branding import apply_excel_hospital_header, auto_fit_columns

async def export_my_entity_excel(db: AsyncSession, current_user: Any) -> BytesIO:
    # 1. Resolve tenant branding
    branding = await BrandingResolverService.resolve_branding(db, current_user)

    # 2. Query domain records (filtered by current_user.hospital_id)
    records = await my_repository.get_all(db, hospital_id=current_user.hospital_id)

    # 3. Initialize Workbook
    wb = Workbook()
    ws = wb.active
    ws.title = "Entity Report"

    # 4. Apply standardized hospital header banner (Rows 1-4)
    # Returns the row index where table headers should be written (Row 5)
    data_header_row = apply_excel_hospital_header(
        ws=ws,
        branding=branding,
        title="Entity Inventory Report",
        record_count=len(records),
        username=getattr(current_user, "username", "System"),
    )

    # 5. Define and write column headers
    headers = ["ID", "Name", "Category", "Amount (INR)", "Status"]
    ws.append(headers)

    # 6. Append sanitized data rows
    for item in records:
        row = [
            item.id,
            item.name,
            item.category,
            float(item.amount) if item.amount is not None else 0.0,  # Native float
            item.status,
        ]
        # ALWAYS wrap in sanitize_excel_row
        ws.append(sanitize_excel_row(row))

    # 7. Auto-fit column widths with padding
    auto_fit_columns(ws, min_col=1, max_col=len(headers))

    # 8. Save and return buffer
    buffer = BytesIO()
    wb.save(buffer)
    buffer.seek(0)
    return buffer
```

### 3.2 Recipe 2: Implementing a Streaming CSV Export

For streaming CSV responses:

```python
import csv
from io import StringIO
from app.utils.csv_security import sanitize_csv_row

async def export_my_entity_csv(records: list) -> StringIO:
    buffer = StringIO()
    writer = csv.writer(buffer)

    # Header
    writer.writerow(["ID", "Name", "Department", "Notes"])

    # Data rows
    for item in records:
        raw_row = [item.id, item.name, item.department, item.notes]
        # ALWAYS wrap in sanitize_csv_row
        writer.writerow(sanitize_csv_row(raw_row))

    buffer.seek(0)
    return buffer
```

### 3.4 Recipe 4: Implementing a ReportLab Platypus PDF Document

For ReportLab Platypus flows:

```python
from io import BytesIO
from reportlab.lib.pagesizes import letter
from reportlab.platypus import SimpleDocTemplate, Paragraph, Spacer
from app.services.branding_resolver_service import BrandingResolverService
from app.utils.reportlab_branding import create_reportlab_header_flowables, NumberedCanvas

async def generate_patient_document_pdf(db: AsyncSession, current_user: Any, patient_data: dict) -> BytesIO:
    # 1. Resolve branding
    branding = await BrandingResolverService.resolve_branding(db, current_user)

    buffer = BytesIO()
    doc = SimpleDocTemplate(
        buffer,
        pagesize=letter,
        leftMargin=36,
        rightMargin=36,
        topMargin=36,
        bottomMargin=45,
    )

    story = []

    # 2. Add standardized hospital branding header (with logo flowable)
    header_table = create_reportlab_header_flowables(branding, title="PATIENT DISCHARGE SUMMARY")
    story.append(header_table)
    story.append(Spacer(1, 15))

    # 3. Add document body flowables
    story.append(Paragraph(f"Patient Name: {patient_data['name']}", styles["Normal"]))
    # ...

    # 4. Build document using NumberedCanvas for dynamic "Page X of Y" and hospital footer
    doc.build(story, canvasmaker=lambda *args, **kwargs: NumberedCanvas(*args, branding=branding, **kwargs))

    buffer.seek(0)
    return buffer
```

## 4. Cache Management & Invalidation

`BrandingResolverService` maintains an in-memory TTL cache (`_BRANDING_CACHE`) with a default TTL of 60 seconds (1 minute).

### When to Invalidate Cache:
Whenever hospital details or logos are updated in `HospitalService`:

```python
from app.services.branding_resolver_service import clear_branding_cache

async def upload_hospital_logo(self, db: AsyncSession, hospital_id: int, file: UploadFile):
    # ... save logo file to disk and update database record ...

    # Invalidate cached branding for this hospital immediately
    clear_branding_cache(hospital_id)
```

## 5. Common Pitfalls & Anti-Patterns to Avoid

| Anti-Pattern | Why It Is Dangerous | Correct Alternative |
|---|---|---|
| **Hardcoding `"NexaCare Hospital"`** | Violates SaaS multi-tenancy. Other hospital tenants see wrong branding. | Always use `branding.hospital_name`. |
| **Using `file://` or raw paths in HTML `<img>`** | Headless Chromium blocks local file system access; logo renders as a broken image icon. | Always use `branding.logo_data_uri` (`data:image/png;base64,...`). |
| **Passing `branding.logo_data_uri` to ReportLab** | ReportLab `RLImage` throws an unhandled exception on data URIs. | Pass `branding.logo_path` or use `create_reportlab_header_flowables()`. |
| **Appending raw un-sanitized rows to Excel** | Exposes the client to **CWE-1236 Formula Injection** (RCE/DDE via `=cmd\|...`). | Always wrap rows in `sanitize_excel_row(row)`. |
| **Stringifying numbers before sanitizing (e.g. `f"-${amount}"`)** | Prevents the sanitizer from recognizing legitimate negative floats, turning them into text strings `'$-150`. | Pass numeric values as raw `int` or `float`. Format formatting rules via Excel cell styles if needed. |
| **Forgetting `current_user` in Route Signatures** | Prevents `BrandingResolverService` from verifying tenant authorization, resulting in fallback to platform branding. | Always inject `current_user: User = Depends(get_current_user)` in route handlers and forward it to service methods. |

## 6. Pre-Merge Checklist for New Export Endpoints

Before submitting a Pull Request for any new export or document generation feature:
- [ ] Route passes `current_user` to the service method.
- [ ] Service resolves branding using `await BrandingResolverService.resolve_branding(db, current_user)`.
- [ ] For Excel exports: `apply_excel_hospital_header()` is invoked.
- [ ] For Excel exports: every appended data row is passed through `sanitize_excel_row()`.
- [ ] For CSV exports: every appended row or dict is passed through `sanitize_csv_row()` or `sanitize_csv_dict()`.
- [ ] For HTML/Playwright templates: `brand_header.html` and `brand_footer.html` partials are included.
- [ ] For ReportLab documents: `create_reportlab_header_flowables()` and `NumberedCanvas` are used.
- [ ] Automated unit test verifies formula sanitization and tenant authorization.
